# 将仓库收敛为 DSH 专用项目

[English](dsh-only-plan.md) | 中文

下一阶段以 DSH 为唯一支持宿主：移除其他适配器及其开发依赖，精简配置和仓库结构，并保持已经验收的原生记忆行为。这项优化优先于[迁移计划](migration-plan.zh.md#phases)中可选的 P5 功能扩展。

优化方向和源码盘点已经落档；下列 S1–S4 实施阶段尚未执行。已验收的 `0.1.0-alpha.1` 代码及其[兼容性证据](compatibility.zh.md)作为起点。本文不宣称删除源码已经降低运行时内存或构建耗时。

<a id="baseline"></a>
## 依据与预期收益

源码基线为 `73cd88b40b2b0852f75ba267100e3ce664aac102`。下表来自该提交的 Git 跟踪文件对象；[机器可读盘点](evidence/2026-09-13-dsh-only-baseline.json)保留精确字节数与路径。统计不包含 Git 对象库、已安装依赖、构建产物和缓存。

| 观测 | 依据 | 本阶段处理 |
|---|---|---|
| 存在八个包工作区，其中七个不属于原生适配器。 | 根 `package.json` 使用 `packages/*`；盘点记录了每个包清单。 | 显式列出工作区，仅保留 `packages/dsh-plugin`。 |
| 根默认命令仍执行 OpenCode、Pi、CLI 和部分 Retina 检查。 | 根 `build`、`typecheck`、`test`、`lint`、`lint:fix` 脚本。 | 默认安装与开发命令直接服务 DSH，不再依赖过滤参数。 |
| DSH 仍有三个来自上游插件目录的源码导入。 | `src/store.ts`、`src/tokenize.ts`，以及 `src/types.ts` 的纯类型导入。 | 删除 `packages/plugin` 前先迁出这些约定及其测试。 |
| DSH 构建已排除庞大的上游宿主和推理入口。 | `scripts/build.ts`、包导出、`NOTICE` 以及隔离安装验收。 | 直接收益是工作区、依赖图和开发维护范围缩小；运行时收益单独测量。 |
| 原有宿主、桌面、Rust 和发布流程仍在仓库中。 | `.github/workflows/`、`scripts/` 和根 Cargo 文件。 | 随源码归属一起移除过时的任务和发布目标。 |

| 跟踪范围 | 文件数 | 字节数 | 含义 |
|---|---:|---:|---|
| 整个基线工作区 | 2,079 | 38,099,062 | Git 跟踪内容约 36.33 MiB。 |
| 原生 DSH 包 | 41 | 172,411 | 不含根锁文件及 DSH 开发文档。 |
| 其他七个包目录 | 1,549 | 22,206,621 | 保留必要源码子集之后的移除候选。 |
| 四个 Rust crate 目录 | 144 | 11,741,951 | 不属于已验收的 DSH 运行路径。 |

七个包目录与 Rust crates 合计 1,693 个文件、33,948,572 字节。这是候选范围的体积，不是承诺删除量：源码迁出和保留测试会新增文件，根文档与脚本仍需逐项核对。删除这些目录不会缩小已有 Git 历史。拟议结果的依赖磁盘占用、构建耗时和最终运行 RSS 尚未测量。对固定版本盘点与实际导入关系的结论置信度高，性能收益待实测。

<a id="ownership"></a>
## 保留、迁出与移除范围

| 范围 | 目标归属 | 必要处理 |
|---|---|---|
| `packages/dsh-plugin/` | 作为唯一包工作区保留。 | 保留 Bundle、四个工具、范围化 SQLite 存储、可回放入场和 DSH Web 记忆管理页。 |
| `packages/plugin/` | 迁出必要源码后移除。 | 仅将 SQLite 约定、检索使用的归一化和受支持分类词表迁入 DSH 包；保留 MIT 署名与源码提交引用。 |
| `packages/pi-plugin/` | 移除。 | 退役 Pi 和 OMP 宿主检测、适配、配置及兼容测试。 |
| `packages/cli/` | 移除。 | 退役 OpenCode/Pi/OMP 安装、诊断和跨宿主迁移命令；安装由 DSH Bundle 流程承担。 |
| `packages/dashboard/` | 移除。 | 退役独立 Tauri/Solid 应用及其签名、发布配置；保留原生 DSH Web 设置页。 |
| `packages/retina-local-fs/` | 移除。 | 退役文档监听、摄取代码和示例，它们不属于本记忆插件的范围。 |
| `packages/docs/` | 移除该工作区。 | 使用现有双语 Markdown 文档，替代上游 Astro/Wrangler 文档站。 |
| `packages/e2e-tests/`、`tests/docker/`、`crates/` | 移除。 | 确认 DSH 测试和脚本没有依赖后，退役旧宿主与 Rust/subc 验证设施。 |
| 根包清单、配置与锁文件 | 按 DSH 精简。 | 移除无用依赖、Cargo 输入、旧别名和命令，根据保留的清单重新生成 Bun 锁文件。 |
| 根 README、架构/布局文档、`.github/`、`scripts/`、历史素材 | 按归属审查。 | 保留 DSH 说明、证据、许可证和有用自动化；移除旧产品及发布输入，历史源码链接改为固定上游版本。 |

OMP 实现在 Pi 适配器和 CLI 内，并不存在独立 OMP 包。`.build/`、`.cortexkit/`、`gate-evidence/` 及非 DSH `docs/` 等根目录同样纳入归属核查，不默认保留；只留下专用项目或署名所需材料，原始历史仍可从 Git 和 `origin_main` 查询。

目标是单包结构：小范围复用源码归入 `packages/dsh-plugin/src/`，聚焦测试归入现有 `tests/`。没有第二个实际消费者，无需另建共享核心包。保持包身份、Bundle 行、工具约定、数据库路径/schema、已有 ID/修订及 Session 投影身份稳定。Bun 继续承担构建和依赖管理，支持的宿主运行时继续为 Node 24 及以上。

<a id="source-extraction"></a>
## 删除前先迁出必要源码

| 当前源码 | 必须保留的约定 | 迁出检查 |
|---|---|---|
| `packages/plugin/src/shared/sqlite.ts` | DSH 存储使用的 Node SQLite 语句、事务/savepoint、位置参数绑定、连接生命周期及失败传播。 | 将相关后端与绑定测试迁入 DSH 套件；裁剪 Bun/Electron 兼容分支或类型依赖前，Node 专用实现必须保留这些行为。 |
| `packages/plugin/src/features/magic-context/memory/normalize-hash.ts` | 检索使用的空白与大小写归一化。 | 保持中文、标识符、路径和混合查询结果，避免改变区分大小写的写入去重；不必复制未使用的上游哈希函数。 |
| `packages/plugin/src/features/magic-context/memory/types.ts` | DSH 工具 schema 支持的七种分类。 | 本地定义保留的词表，不引入上游整套记忆接口，也不扩大可接受值。 |
| 上游小模块测试和 DSH 构建/CI 引用 | 保留行为的验证与独立安装产物。 | 同阶段更新 `.github/workflows/dsh.yml`、声明/导出、`NOTICE` 及源码链接；导入和绑定检查仅扫描保留的 DSH 源码。 |

不迁入上游完整记忆存储、embedding 缓存、Historian、Dreamer 或完整配置 schema。适配后的源码纳入版本管理，保留原始路径、提交、许可证及简短的下游变更说明。历史署名可以出现 OpenCode/Pi；可执行导入、工作区清单、包导出和 CI 命令不得依赖已移除的适配器。

## 实施顺序

| 阶段 | 状态 | 交付物 | 完成证据 |
|---|---|---|---|
| S0：盘点与范围确定 | 本计划已完成 | 固定源码体积、三个导入边界、候选移除清单和收益边界。 | 本文记录可复现 Git 盘点和源码/包清单核查。 |
| S1：DSH 源码独立 | 待实施 | 本地源码子集、Node 专用 SQLite 接口、迁移后的行为测试、声明与署名更新。 | 不再从其他包目录导入编译期或运行时代码，DSH 检查与产物构建通过，已有数据库和回放行为保持有效。 |
| S2：裁剪工作区与依赖 | 待实施，依赖 S1 | 移除七个非 DSH 包目录及 Rust/旧宿主专用设施，精简根脚本并重新生成锁文件。 | 干净工作区只有一个包，默认安装/构建/检查不要求旧宿主、Cargo、私有兄弟仓库或可选推理运行时。 |
| S3：统一 CI、发布与文档 | 待实施，依赖 S2 | DSH 专用 CI 与根项目入口，退役上游发布/签名任务，采用选择性上游维护。 | 活跃命令、导出和工作流不再引用已移除的归属模块，双语文档及本地链接校验通过。 |
| S4：行为验证与收益测量 | 待实施，依赖 S3 | 新验收记录、隔离安装包、前后测量及回退证据。 | 下列功能、打包、配置和资源标准在精确结果提交上通过。 |

每个实施提交都应让保留的 DSH 路径可审查、可使用；迁移源码时同步迁移检查它的测试/CI 引用，删除工作区时同步删除根命令和配置引用。文件系统删除使用 `trash`。本阶段调整仓库代码和构建归属，用户记忆数据库、Session 日志、正式 profile 和无关机器缓存不属于清理对象。

## 验收与测量

| 关注点 | 必须观察到的结果 |
|---|---|
| 仓库归属 | 恰好一个 DSH 包工作区；可执行导入、路径别名、声明和构建/测试命令均不需要已删除包目录。 |
| 依赖闭包 | 干净环境可按冻结锁文件安装，无需旧工作区；依赖分别归属 DSH 宿主、客户端、构建或测试，移除无用直接依赖，不能仅凭名称删除宿主需要的间接包。 |
| 记忆语义 | 保留 Node SQLite 原子性、重试/幂等、修订、归档、项目/全局访问、中文/混合检索和失败处理；保留行为覆盖，不依赖测试数量不变。 |
| Session 语义 | 保留入场前取消、已记录内容冻结、JSONL 重启/回放、fork 隔离及原生压缩共存。 |
| 界面与安装包 | 在工作区外安装 tarball，执行生产 JSX factory，并在 DSH Web 验证列表、编辑、归档和 JSON 导出。 |
| 真实模型 | 在隔离 home/profile 中复用正式 Ollama Cloud 的 `ollama/deepseek-v4.1-flash` 路由，重跑现有十场景并记录结果和用量。 |
| 性能 | 复用现有 1,000/10,000 条记忆、短/长历史负载、宿主版本、机器和资源门槛；分别记录安装体积、依赖数、构建/检查耗时、安装包体积、查询延迟和 RSS。 |
| 来源与文档 | 保留 MIT 说明及精确源码来源，修复源码/声明链接，新增证据而不覆盖历史验收测量。 |

<a id="upstream"></a>
## 保留来源并防止其他适配器回流

`origin_main` 继续通过快进更新镜像官方完整源码。`dsh_main` 承载专用产品，仅选择性采纳与保留模块有关的已审查修复。专用分支不再例行合并完整上游镜像，以免重新带入范围外文件并引发删除/修改冲突；迁入必要源码修复时记录原始提交并做聚焦验证，只有提交内每个改动路径都属于保留范围时才适合整提交 cherry-pick。操作步骤由[上游工作流](../../UPSTREAM.zh.md#synchronize)维护。

S1 前记录已验收源码提交和安装包校验值。回退仓库改动时 revert 对应精简提交，或使用该基线的独立工作区；不改写上游镜像和 Git 历史。本优化保持现有记忆及 Session 格式稳定，因此回退不应要求数据转换；如确实需要 schema 变更，应作为独立变更提供迁移证据。

S1–S4 具备验收证据、正常项目路径仅服务 DSH，且每个保留的非 DSH 名称依赖或源码文件都有实际 DSH 用途，才算完成本计划。Embedding、更广泛的语义召回评测、后台提取、新宿主、npm 发布和正式 profile 启用继续作为独立工作项。
