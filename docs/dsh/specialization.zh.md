## 可比资源测量

原样复用的 worker、夹具路径助手和记录型 adapter 通过源码哈希核对。两个产物版本在不同进程中使用同一 cwd，运行相同的 1,000/10,000 条记忆及 100/10,000 条历史事件负载，排除检出路径长度对工作区元数据序列化的影响。实测 Host JavaScript 与最终 tarball 逐字节一致。

| 指标 | 1k 前 | 1k 后 | 10k 前 | 10k 后 | 门槛 |
|---|---:|---:|---:|---:|---:|
| 存储打开，ms | 2.163 | 2.487 | 2.157 | 2.238 | ≤100 |
| 查询 p95，ms | 0.250 | 0.270 | 0.867 | 0.818 | ≤25 |
| 快照 p95，ms | 0.196 | 0.200 | 1.489 | 1.275 | ≤25 |
| 含框架快照估算 | 860 | 860 | 863 | 863 | ≤1,000 |
| 新增采样峰值 RSS，MiB | 12.06 | 15.08 | 44.80 | 20.98 | ≤64 |
| 保留投影，字节 | 52 | 52 | 52 | 52 | ≤128 |
| 辅助模型调用 | 0 | 0 | 0 | 0 | 0 |
| 新增长期驻留进程 | 0 | 0 | 0 | 0 | 0 |

现有门槛全部通过。1k 负载的启动/查询/快照略有回退，采样峰值 RSS 增加 3.02 MiB；10k 的查询/快照/RSS 观测改善，但启动略慢。没有为这些波动归因于已确认原因。每组只有一轮可比测量，不能据此证明稳定的运行时收益。RSS 是相对于 DSH 服务/历史基线的进程采样差值，不是整个 Web 进程的内存上限。

最终干净检出的普通 benchmark 也通过。它的快照 token 数可能随夹具绝对路径变化，因此前后结论采用可比测量。历史基准数据没有覆盖。

## 真实模型验收

最终完整矩阵通过全部十场景：保存、新会话召回、工作区隔离、修正、修正后召回、归档、归档后召回、精确历史事件引用、显式全局写入和跨工作区全局召回。脚本校验真实 Session 日志、存储记录、工具结果及 Ollama 路由。总耗时 73.664 s，共 27 次普通模型请求，关闭标题生成，无本地 Ollama daemon。

| Provider 上报计数 | 成功矩阵 |
|---|---:|
| 输入 token | 143,920 |
| 缓存读取 token | 383,232 |
| 输出 token | 4,254 |
| 总 token | 531,406 |

保留了两次前置尝试：一次请求暴露宿主运行时分裂，另一次共 22 次请求的尝试在历史指令与判定不匹配处停止。所有尝试合计 50 次请求，上报输入 276,682、缓存读取 697,472、输出 7,781、总量 981,935 个 token。这些计数不是费用估算。

运行失败发生在记忆工具执行之前：npm 为 profile 安装了一份 `dsh-tools`，launcher 则提供了另一套 AgentLoop 依赖树。两份模块版本号相同，但内部调度 Symbol 不同。通过 `dsh plugin` 配合 `--config.auto-install-peers=false` 安装后恢复为同一宿主模块图。真实测试现已在请求模型前检查这一条件，并记录实际模块哈希；正式运行环境未修改。

历史场景最初要求读取任意相关事件，但严格判定要求已读取事件包含更正值。模型读取了前置 recall，只通过检索找到真正更正。当前指令明确要求读取并引用更正事件，判定标准保持严格；下一轮完整矩阵通过。

## 复现与维护

在仓库根目录执行默认流程：

```sh
bun install --frozen-lockfile --ignore-scripts
bun run check
bun run build
bun run test:install
bun run benchmark
actionlint .github/workflows/dsh.yml
```

新旧数据验证时，将 `DSH_MEMORY_BASELINE_STORE` 指向已验收产物安装目录内的 `dist/store.js`，再执行 `bun run test:rollback`。可比测量将基线原生包目录传给 `node packages/dsh-plugin/scripts/compare-benchmarks.mjs`；该目录需要原始 worker/测试源码、已发布测试依赖及已验收 `dist/` 文件。两个版本会自动共用新建临时 cwd。

真实模型验证按[包指南](../../packages/dsh-plugin/README.zh.md#真实模型验证)准备隔离 profile，设置 `DSH_MEMORY_TEST_HOME` 后执行 `bun run test:live`。脚本拒绝标准正式 home，并创建全新合成工作区；排查失败时保留原始回执。

运行依赖仍是两个 schema 库和 DSH/Cordis peer。React 与 DSH 客户端 peer 属于可选 Web 界面。TypeScript、Biome、tsx、类型包及宿主测试/持久化/压缩夹具属于开发。保留 `koffi` 和 `@deepseek-ai/node-addon-system` 是因为 DSH JSONL 持久化需要它们，对应平台包不是推理后端。移除的直接开发依赖为 `@types/better-sqlite3`、`@types/react-dom`、`react-dom`。

包保持私有。此验收覆盖指定本地运行时及桌面浏览器，对实际夹具观测具有高置信度。Linux CI 执行、其他 DSH 版本、其他视口、npm 发布、正式 profile 启用、embedding 和后台提取不在本记录覆盖范围。选择性维护遵循[上游工作流](../../UPSTREAM.zh.md)，并保留 [MIT 来源说明](../../packages/dsh-plugin/NOTICE)。
